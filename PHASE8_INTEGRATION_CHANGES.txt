SECTION 1 - BACKEND CHANGES (repo: /Users/mac/Desktop/ai-content-agents)
=================================================================================

1.1  NEW  backend/auth/jwt.py
     Zero-dependency HS256 JWT verify + encode (stdlib hashlib/hmac/json/struct).
     - verify_hs256(token, secret) -> payload with claim checks:
         exp (required), nbf, iat, iss, aud (optional, validated when provided).
       Constant-time compare via hmac.compare_digest.
     - InvalidTokenError(ValueError) carries a human 'reason'.
     - encode_hs256(...) exists ONLY for tests / local token minting (never prod).
     Why: backend previously had NO jwt library. Avoids adding python-jose.

1.2  NEW  backend/auth/supabase.py
     SupabaseAuthVerifier - dual strategy:
       - If settings.supabase_jwt_secret is set: local HS256 verify (no network).
       - Else: GoTrue introspection  GET {SUPABASE_URL}/auth/v1/user
         with the anon key (works without sharing the JWT secret).
     Returns SupabaseProfile(sub,email,name,role).
     SupabaseAuthError raised on any failure (bad signature/expired/denied).

1.3  backend/auth/service.py
     - NEW find_user_by_id(conn, user_id) -> {id,email,name,initials,role}
       (real AuthUser was missing 'name'; fixed the mapping).
     - NEW ensure_supabase_user(conn, *, sub, email, name, role):
       auto-provisions the platform users/profiles/user_roles rows on first
       login. Platform user id == Supabase sub. password_hash is a placeholder
       (password login is de-emphasized; Supabase is the identity provider).

1.4  backend/deps.py
     get_current_user now: request:Request + db + authorization header.
       - Builds SupabaseAuthVerifier from settings (supabase_url/jwt_secret/anon_key).
       - Verifies the JWT, maps sub -> platform user (auto-created on first login).
       - 401 on any failure. Semantics rewritten to "Supabase-first".

1.5  backend/config.py
     Settings gained: supabase_url, supabase_jwt_secret, supabase_anon_key
     (each "" default, read from env). CORS/router wiring unchanged.

1.6  src/validation/review_schema.py
     - ReviewAction now includes NEEDS_EDIT="needs-edit" and FLAG="flag"
       (the action map referenced these but the enum lacked them).
     - apply_review: terminal statuses allow COMMENT/FLAG; needs-edit and edit
       go to OutputStatus.EDITED. needs-edit does not require edited_payload;
       stores payload only when provided.
     - AgentRun gained mark_finished(status=SUCCESS) helper.

1.7  .env.example appended Supabase section (URL / JWT_SECRET / ANON_KEY)
     explaining local-HS256 vs GoTrue strategy + NEVER commit secrets.

SECTION 2. BUGS FOUND BY RUNNING THE REAL SERVER (fixed here)
=================================================================================
These only surfaced with a real request flow (tests stub the retrieval layer,
so they never reached these lines). Found & fixed while proving the slice:

2.1 backend/chat/service.py:216 and backend/generation/service.py:111
     Used `chunk.chunk_id` / `chunk.text` but RetrievedChunk wraps a nested
     `.chunk`. Fixed to `chunk.chunk.chunk_id` / `chunk.chunk.text`.
     (caused AttributeError on real /generate/questions and /chat.)

2.2 src/validation/review_schema.py  AgentRun.mark_finished
     Chat/generation services call run.mark_finished() but AgentRun had no
     such method. Added mark_finished() -> sets status=SUCCESS + finished_at.
     (matches the orchestrator's existing run.status/run.finished_at pattern.)

2.3 backend/review/service.py  perform_review_action_service
     Was `updated_output, review_rec = apply_review(...)` but apply_review
     returns a single Review (it mutates the output in place).
     Fixed to `review_rec = apply_review(...)` + save the mutated output.
     (caused ValueError on POST /review/approve.)

SECTION 6 - REMAINING BLOCKERS / DEMO NOTES
================================================================================
1. Backend live generation needs a real model. Local trusted path used the
   pre-existing LITELLM_BASE_URL/API_KEY + DEFAULT_MODEL
   (gemini/gemini-flash-lite...) already present in the backend .env. Pass that
   model id (or leave model unset -> DEFAULT_MODEL) on /generate/*. Passing
   model="mock" returns 403 (gateway - there is no mock fallback on the backend).
2. The 7 failed/4 errored tests (InsufficientGroundingError) are a PRE-EXISTING
   chroma persistence quirk (confirmed on untouched baseline via git stash),
   not a product of Phase 8. It does not affect the live server which uses a
   real on-disk chroma dir (the live slice embedded + searched + generated fine).
3. Frontend currently needs .env.local API_BASE_URL=http://localhost:8000 (not
   "/api") to leave mock mode. User should run `npm run dev` with the backend
   up to see the real BackendStatus + upload/google-sheets/export flow in the
   browser.
4. No secrets were committed. Supabase anon key is publishable; the JWT secret
   lives only in the backend .env (not committed). Placeholders are in .env.example.
