------------------------------------------------------------------------------
ROOT CAUSE
------------------------------------------------------------------------------
The Dashboard Home page (src/routes/home.tsx) rendered the "Continue Studying"
card from hardcoded strings, not from workspace data:

  - "Chapter 3 — Data Types & Variables"       (hardcoded title)
  - "You reviewed 12 of 25 grounded questions" (hardcoded copy)
  - "18 min left"                              (hardcoded)
  - "Introduction to Python"                   (hardcoded)

The card never read from useWorkspace() at all, so it could not react to new
documents, workspace switches, refreshes, or re-login. The rest of the page
already consumed real data (the "Recent documents" grid renders
data.docs.slice(0, 4)), confirming the persisted documents already live in the
workspace store via the bootstrap query.

No mock values remain in the card, and no new fetching was added — the card
derives from the existing reactive workspace store, so it updates automatically
whenever documents change, the active workspace changes, the page refreshes, or
the user logs in again.

NEW DATA FLOW
------------------------------------------------------------------------------
  Documents are persisted by the Phase 7.3 fix (src/routes/library.tsx ->
  DocumentService.createDocument -> src/api/document.api.ts -> Supabase
  `documents` table). The Workspace bootstrap
  (getWorkspaceBootstrap in src/api/workspace.api.ts) already loads those rows
  per workspace into the React Query cache keyed
  ["workspace-bootstrap", user?.id], and WorkspaceContext.addDoc prepends to
  the in-memory store + invalidates that query.

  Home page "Continue Studying":
    useWorkspace().data.docs  ->  newest doc  ->  card
                    (reactive, no manual refresh, no new API call)

  Update triggers:
    - new text document created  -> addDoc mutates the store + refetch
    - workspace switch           -> activeId changes, store slot swaps
    - page refresh               -> bootstrap refetches from Supabase
    - login again                -> AuthContext purges cache, bootstrap refetches
