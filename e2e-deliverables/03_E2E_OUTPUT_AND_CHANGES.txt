PART D — FINAL STATUS
---------------------
  Workable end-to-end at the API level with a local HS256 session:
    login -> workspace -> upload/parse/chunk/embed -> search -> generate(grounded)
    -> review approve/reject (+audit) -> export (approved only, gate enforced).

  NOT provable in a real browser because:
    (1) Supabase anon key is invalid/revoked -> Supabase login 401. Replace with a
        valid project anon key or sign your own HS256 JWT and paste it into the
        Authorization header.
    (2) LiteLLM proxy token went invalid mid-run (401 token_not_found_in_db) -> the
        proxy must re-issue a valid key for reliable generation.
    (3) The grounding guard is content/query dependent -> some texts surface
        InsufficientGroundingError as a 500 (baseline behaviour, unchanged).

       in ai-content-agents/.env.

    3. In the browser: login -> workspace -> upload a real .txt -> search -> generate
       -> review -> export. Every step is wired to the real backend; the only things
       that can fail are the two external credentials.
