PHASE 7.3 — DOCUMENT PERSISTENCE HOTFIX
=======================================
Date: 2026-08-06
Status: COMPLETE (type-check, lint, build all green)

Two blocking issues were fixed:
  1. "Select files" upload on the Library page did nothing.
  2. Text-created documents lived only in React/localStorage state and were
     lost on refresh, logout, or workspace switch.

------------------------------------------------------------------------------
ROOT CAUSE
------------------------------------------------------------------------------
Issue 1 — upload button was a fake:
  - src/routes/library.tsx "Select files" onClick fabricated a document via
    addDoc(...) locally. There was no file picker, no file read, no storage
    write, and no document record. It "worked" only until refresh.
  - src/routes/library.tsx dropzone onDrop also just fabricated a document.
  - UploadService / DocumentService existed but were dead code — no UI called
    them. No Supabase Storage object was ever created and no documents row
    was ever inserted.

Issue 2 — text docs never persisted:
  - WorkspaceContext.addDoc only called mutate() (in-memory store +
    localStorage). It never touched a service, the API layer, or Supabase.
  - The non-mock workspace bootstrap (getWorkspaceBootstrap) seeded the store
    from mock seed data instead of loading real documents from the
    `documents` table, so a refresh wiped user-created material.

------------------------------------------------------------------------------
WHAT WAS CHANGED
------------------------------------------------------------------------------
New document flow (non-mock):
  Frontend → supabase.storage.from("documents").upload() (bytes)
           → documents row insert (record, client uuid preserved so the
             storage path <workspaceId>/<uuid>/<fileName> matches the row)
           → best-effort parse/chunk/embed via FastAPI (skipped gracefully
             when FastAPI is down — the persisted upload is never lost)
           → queryClient.invalidateQueries(["workspace-bootstrap"]) so the
             library refreshes from the DB and survives refresh/logout/switch.

Files modified:
  - src/types/domain.ts
      WsDoc gained optional storagePath and sizeBytes.
  - src/types/api/document.contracts.ts
      Added CreateDocumentRequest/Response and UpdateDocumentRequest.
  - src/api/document.api.ts
      Rewritten. uploadDocument now writes the real file bytes to the private
      `documents` bucket at <workspaceId>/<id>/<fileName>. createDocument
      inserts the `documents` row (RLS scopes to the workspace owner),
      mapping size_bytes/pages/chunk_count/status/storage_path/notes/topics,
      and returns the persisted row mapped back to WsDoc (mapDocumentRow).
      updateDocument / deleteDocument persist edits and best-effort storage
      cleanup. getDocuments and new getDocumentsForWorkspaces load real rows
      (newest first). parse/chunk/embed pipeline calls kept. Mock branches
      preserve previous behaviour (doc- ids are guarded by isUuid so they can
      never be sent to the DB).
  - src/api/workspace.api.ts
      getWorkspaceBootstrap (non-mock) now loads real docs per workspace via
      getDocumentsForWorkspaces instead of seeding from mock data. The mock
      branch is unchanged.
  - src/services/UploadService.ts
      store() now persists the document record via documentApi.createDocument
      and returns the stored WsDoc. ingest() runs upload → store → best-effort
      parse/chunk/embed with logger.warn on enrichment failure.
  - src/services/DocumentService.ts
      Added createDocument(workspaceId, doc) and updateDocument(workspaceId,
      id, patch); kept listDocuments/listChunks/saveNotes/deleteDocument.
  - src/contexts/WorkspaceContext.tsx
      addDoc is now async: persists via DocumentService.createDocument, then
      prepends the persisted doc to the store (deduped by id), then
      invalidates ["workspace-bootstrap"]. updateDoc/removeDoc remain
      optimistic with DocumentService persistence and logger.warn on failure.
  - src/routes/library.tsx
      "Select files" opens a hidden <input type="file" accept=".pdf,.docx,
      .pptx,.txt,.md" multiple>. handleFiles loops UploadService.ingest per
      file → addDoc → toast. The dropzone now calls the same handleFiles.
      saveDraft (new written material) is async and persists via addDoc,
      showing a toast on failure. Uploading state disables the button.

REMAINING KNOWNS
------------------------------------------------------------------------------
  - With VITE_ENABLE_MOCK=false and no FastAPI running on :8000, the
    parse/chunk/embed enrichment stages fail fast but are swallowed by
    UploadService (logger.warn), so uploads and notes still persist. Chunk
    counts and embedded counts stay 0 until FastAPI is up.
  - Storage RLS (migration 012) only lets the workspace owner upload; staff/
    reviewers get SELECT only (011). A staff member cannot upload into a
    student workspace by design.
  - New text notes persist with status "Ready" (indexed) and chunk_count 0
    until the parse/chunk pipeline runs against real documents.
